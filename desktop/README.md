# StudyFlow 学程桌面

> **仅供学习用途，严禁用于刷课。** 请遵守平台规则、课程要求及学术诚信规范；不得用于代学、代考、伪造学习记录、绕过本人验证或批量获取学分。

本地 Windows Qt 控制台，连接已经运行的 StudyFlow MCP，复用账号、登录态和浏览器。

## 打开

在持有现有账号的 MCP 上调用 `start_desktop_console`，`app_path` 指向本目录的 `app.py`。可指定本机 Python 路径。配对信息仅通过进程管道传递；不复制 Cookie、不重登、不重启浏览器。

直接运行 `app.py` 是界面预览，不会建立账号服务。此版本尚未打包为独立安装程序。

## 使用

- 账号与浏览器：顶部切换当前账号，显示最近实际媒体采样和采样时间。刷新读取缓存，既有窗口可以显示或最小化。
- 课程队列：读取课程、勾选多门、拖动排序，选择新浏览器模式和倍速，然后启动。已运行账号的相同队列复用；每门课程内顺序推进，完成后继续下一门。暂停只停止该账号调度。
- 考试工作台：选择课程并打开考试列表，由本人完成验证。支持整卷预览、仅审阅及连续暂存，已审阅答案不重复调用模型，最终整卷回读。本人提交后识别平台回执，再切换下一门课程。自动交卷默认关闭；明确勾选后按可见剩余时间阈值执行一次，默认40分钟。
- 模型服务：服务商、接口、模型及输出上限可选择；密钥仅存内存。播放、状态更新和填写不调用模型。模型不确定或证据不足时保留待处理状态。
- 模型默认直接连接服务；需要代理时可勾选系统代理。多选理由数组会由 MCP 从已有的逐项证据规范化；预检失败时显示具体原因，填写前停止。
- 邮件通知：共享发件配置，每账号分别绑定收件邮箱，沿用验证截图、小时汇总和异常通知。SMTP 接收不代表已确认收件箱送达。
- 实时进度：每个账号现有 Playwright 工作线程每2秒直接读取 video.currentTime、paused、ended、playbackRate 和解码帧数。软件每2秒读取该账号缓存，不依赖页面推送，不按时间估算进度；读取延迟会明确标记。暂停/结束事件仍负责快速恢复与接续。
- 账号与课程：添加账号只填账号、密码和可选邮箱；先登录读取本账号课程，再到课程队列勾选。没有选择课程前不会为该账号启动浏览器。课程读取显式限制当前账号。
- 打开账号浏览器：默认无头学习；点击后只暂挂该账号队列，将 Cookie/localStorage 在内存中迁移到有窗口的独立浏览器。你可以进入考试并手动拖动验证码。已开始的考试或未知提交结果禁止替换；迁移失败保留原浏览器。完成操作、返回课程后点击“返回后台学习”恢复无头队列。其他账号不受影响；“只读预览”仍可不迁移地查看页面。
- 事件记录：按当前账号显示中文摘要，可切换全部账号、答题/播放/课程/邮件/错误分类、关键词过滤；原始技术详情默认折叠。最多保留1500个本次会话事件。密码、密钥、Cookie、页面签名脱敏，不记录模型思考过程。
- 模型配置：参考 CC Switch 的多配置管理，支持服务商预设、自定义配置名、新增/复制/删除、读取模型及延迟、切换、代理、推理强度、输出上限、兼容 JSON 导入和无密钥导出。配置与密钥仅在后端内存中保存；进行中的审阅继续使用它启动时的配置。当前调用协议为 OpenAI 兼容 Chat Completions，Anthropic 原生配置会明确提示而不会假装导入成功。
- 审阅前失败：证据不确定允许一次材料复核，本地预检失败允许一次结构修正；仍未通过则保留现场。提交后结果未知不自动重交。
- 学习日志默认只记录平台确认完成的课程、题目/答案/平台正确率和邮件实际主题、收件邮箱、内容摘要及 SMTP 结果；重复状态不刷屏。发信记录从新版本加载起保存在进程内存中，旧邮件没有明细时不补造记录。技术日志需手动展开。
- 模型页提供13家云服务商预设以及 Ollama/自定义入口；新增服务商只配置地址，仍需用户输入该服务商密钥、选择可用模型，不自动改变正在使用的 DeepSeek。

关闭桌面窗口不会关闭 MCP 或课程浏览器。连续考试填充会在当前动作结束后停止；已经授权的后端交卷等待可先点击“停止脚本”。验证码、人脸验证由本人完成。

## 验证

`python -m unittest test_core test_ui` 测试桌面路由、审阅、未知结果不重放、三账号交互及界面布局。MCP 测试中的隔离浏览器试卷拦截所有网页请求，仅验证脚本，不重复提交真实考试。三账号实际登录、课程读取和邮件映射记录在本聊天 outputs 中。


窗口入口：有头和无头都由原账号队列自动调度。打开账号窗口不等于手动暂停；验证码、活动考试和未知提交保留守卫。已关闭的账号浏览器经守卫核验后独立恢复。
播放结束的历史样本显示“播放已结束 · 待平台确认”，不误称实时采样；完成以平台任务标记和独立目录为准。

软件默认启用用户授权的单次补播策略：运行账号策略缺失时通过原连接单独更新，不重载执行代码、不重启浏览器、不清零次数。仅真实结束、唯一任务、平台 isPassed=false 时补播一次；已完成任务不重播，未知提交及验证守卫优先。事件记录按账号显示补播登记、启动和平台确认；一次后仍未确认则保留现场。

诊断联动：当前聊天通过已有鉴权 MCP desktop_console_status 读取界面心跳、每账号错误及 recent_rpc_faults；接口不冒充独立后台模型进程。HTTP 会话按工作线程隔离；状态只读重试一次，提交不重放。
题目状态显示正在完成章节测验/正在处理视频弹题，点击查看题目与正确率按账号打开题目、答案与实际判分日志；证据不足先补取完整当前课程字幕核对一次，不编造正确率。
邮件：普通任务推进只纳入每小时汇总；整门课程完成的自动邮件每账号最短30分钟；人脸新二维码去重且最短5分钟，首次验证提醒不延迟。

2026-10-24运行复盘：模型JSON包装提取、有限闭合括号修正后仍完整校验答案；单选判断仅使用必要字段。已明确判错的弹题在新课程证据与实际错误反馈下只允许一次新审阅纠正，未知提交不重放。当前聊天审阅可附到章节/题目指纹绑定的计划，经软件原流程执行；题目变化则回退配置模型。平台评分由各账号原进程内报告事件恢复显示。缓冲30秒无进展时，每一停滞位置仅一次正常暂停/播放恢复；已初始化且未结束的视频使用正常HTML媒体play()继续，避免误点大播放按钮重置源。

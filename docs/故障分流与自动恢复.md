# 故障分流与自动恢复

仅供学习用途，严禁用于刷课。

失败按账号、任务和故障现场隔离。只读查询、媒体播放、模型处理、写入及本人验证分别判断；其他账号继续执行。

| 失败类型 | 自动动作 | 恢复条件及边界 |
| --- | --- | --- |
| 浏览器状态查询 | 读取本地连接/关闭标志，不排队浏览器RPC；保留故障标识 | 不把控制线程异常冒充浏览器关闭 |
| 原控制线程的只读超时 | 无待提交时，在原FIFO队列做一次只读探测；新故障现场可重新探测 | 原线程响应才解锁；已关闭页只恢复本账号；真正无响应继续保留现场 |
| 恢复后同位置再次故障 | 只有晚于本次故障的新鲜正常播放样本才结束该故障周期、重置恢复额度 | 旧running快照、暂停、过期样本都不清除额度；提交去重不受影响 |
| 只读探测迟到 | 消费已发出探测的原回执，不再排入相同探测 | 只解除对应故障；后续写入超时不会被较早只读结果掩盖 |
| 弹题提交的明确评分迟到 | 原线程结束后，核对本次题目、答案、原生点击与明确评分记录，再探测原页面 | 未知结果、旧记录、身份不符、重复回执均保留保护；不重答 |
| 提交前读取选项失败 | 原子读取选项；确认原操作结束且没有提交、完整未判分题目一致后，释放遗留审阅计划一次 | 只解除该账号同题的去重记录；场景变化、已经提交、重复失败不放行 |
| 提交后回执超时 | 核验原计划、测验身份、逐题评分；队列忙或待判分时有限只读复核 | 完整评分确认才接续；不重交、不用普通播放恢复绕开提交保护 |
| 控制线程健康但平台尚未判分 | 同样进入原计划只读回查，不要求先出现控制线程故障 | 没有评分不重复提交；确认后继续原队列 |
| 评分回查本身超时 | 原探测及其回执保存在内存，后续只消费原回执 | 浏览器代次或计划变化则拒绝套用；不排入重复探测 |
| 打开/关闭/恢复账号 | 同账号生命周期动作互斥，按钮显示处理中 | 活动考试、未知提交先核验；健康账号不重建 |
| 未启动账号直接打开课程考试 | 仅启动所选账号工作区，保留课程选择，启动后自动接续入口 | 不启动历史课程队列；启动中最多等待90秒，账号或课程已切换的旧回调失效；登录或本人验证保留明确状态 |
| 未启动账号查询考试进度 | 返回未启动、0题，不启动浏览器或队列 | 不把正常未启动状态报告为工作进程故障 |
| 考试同组某题检索缓慢或失败 | 已确定答案先进入暂存，检索只处理剩余题目 | 浏览器写入由单线程顺序执行，不与模型线程并发点击 |
| 单题审阅字段格式不一致 | 规范化已有逐项字段，格式失败只修复该题一次，其余有效题目继续 | 不虚构依据或置信度，不清除显式冲突；未知保存仍只回读 |
| 末题保存后预览内容延迟加载 | 在原15秒期限内等待完整题目内容；只重复读取，不重复点击 | 身份、锁定或到期错误立即保留；完整预览逐题一致才确认全部保存 |
| 连续保存返回工作进程异常 | 先读取原页面，整卷全部匹配时收尾 | 未确认全部匹配仍保留现场，不重放保存；再次执行已完成试卷先只读审计 |
| 原试卷标签页已关闭、列表仍开着 | 打开同课程考试时复用原上下文，只恢复曾观察并验证身份的原预览地址，回读既有答案 | 不新建考试、不重复保存或交卷；异卷、未知写入或答案不一致保留错误；重复恢复复用原页 |
| 新故障继承了旧恢复编号 | 状态接口使用本次超时唯一编号，旧版无编号才回退到原日志时间 | 不让已消费的旧探测拦住新的独立故障；未结束原操作仍保留现场 |
| 旧版只读探测已经消费却仍保留锁 | 原线程队列空闲、无未知题目写入且无活动考试时允许一次新的FIFO只读探测 | 不重复排入仍在等待的探测，不重启浏览器，不解除提交保护 |
| 同一卡片多个视频弹题 | 仅读取当前未完成视频的弹题，已完成或后续视频残留弹题不参与本题 | 所有读取、填写、回读绑定同一视频任务；当前视频已完成则先核对目录 |
| 弹题已消失但旧审题事件迟到 | 重新观察当前任务，媒体正常播放或平台完成时接续 | 未知结果不解除保护；恢复确认后从当前故障中清除通信错误，保留历史日志 |
| 已结束账号的延迟故障事件 | 返回“未启动”，不再尝试恢复原队列 | 不把没有浏览器当作损坏，不自动重新开始已结束任务 |
| 恢复后监听已停止 | 重启原任务的受保护监听，再接续队列；弹题转审题、验证转本人验证、完成转目录 | 不直接盲点播放；同章节的新视频或新暂停现场分别计次，同一现场去重 |
| 媒体停滞 | 核对原视频、任务标记与画面采样，走正常播放恢复 | 不拖动，不伪造完成；每段身份独立 |
| 模型或检索失败 | 保留已确定结果，只重试待处理部分 | 不把单题检索失败扩散到整组或其他账号 |
| 平台已判错、模型仍重复原答案 | 本轮明确授权的账号可调用播放器原生继续，保留错答并接续原队列 | 策略按账号在后台内存保存，默认不启用；未知结果不适用，不改分、不重复交答卷；重现弹题仍校验原题及原生继续回执 |
| 模型网络超时、断连、429或5xx | 当前账号按5、15、30秒最多再试三次，先重新观察题目；显示重试倒计时和次数 | 未提交的模型调用可重试；认证失败、证书错误、缺配置和未知提交不走此路径；可能产生额外模型调用费用 |
| 恢复检查暂遇加载中或通信失败 | 同样有界退避检查，其他账号独立调度 | 仅重新检查，不按泛化异常重交答案；耗尽后保留明确错误 |
| 任务线程启动失败 | 释放该账号的忙碌标记，保留失败任务回执 | 不让一个未启动线程永久占用账号；其他账号继续 |
| 单账号状态数据或调度异常 | 捕获在该账号边界内，下一账号仍调度 | 错误类型进入事件记录，不输出异常正文中的密钥或网址 |
| 本地进度文件写入被拒或磁盘故障 | 保留内存队列和旧原子检查点，下次保存重新尝试 | `checkpoint_error_type`明确记录落盘失败；不因此中断播放，也不声称新进度已持久化 |
| 首次并发创建邮件额度文件 | 先取得OS字节锁，再初始化额度文件；同一额度仅一次获准发送 | 保留跨进程限流；未知发送仍占用原额度，不借恢复重发 |
| 本人验证 | 暂停该账号，失效二维码正常刷新后发送新图 | 本人完成后重新核验，其他账号继续 |
| 教师未发布 | 留在待补清单，继续其他可用任务 | 不记为完成，等待平台发布 |

原操作尚未结束或评分未返回时，后台保留只读跟进；收到明确结果再接续。人工暂停的账号不自动恢复，未知提交不重新执行。

恢复结果显示原始故障类型、正在执行的动作以及成功/待处理结果。历史错误保留；新状态以实际回读为准。此表描述已实现流程和保护条件，不承诺未来平台变化均可自动处理。

浏览器工作线程异常另外保留操作名、异常类型及末尾调用栈的文件名/行号/函数名，便于定位被通用提示遮住的实际失败；该诊断不记录异常正文、调用参数或页面地址。热加载需同步审阅字段依赖后再更新服务方法，避免文件已更新而进程继续使用旧依赖。

## 故障锁检查范围（2026-11-01）

本轮区分三类状态：线程/账号互斥用于防并发，故障去重用于防恢复风暴，提交保护用于防重复写入。只在对应证据成立时解除，不通过清空全部锁恢复运行。

| 锁或约束 | 解除路径 | 回归文件 |
| --- | --- | --- |
| 后台active、请求ID去重、审阅账号锁 | 正常结束或异常finally释放；线程未启动也释放；同请求返回原回执 | test_application_service、test_fault_lock_lifecycle |
| 自动审阅与故障场景去重 | 正常新任务、真实恢复样本；已分类的模型瞬时错误走独立有限额度 | test_application_service、test_fault_lock_lifecycle |
| 浏览器worker_failed、FIFO探测 | 同故障原探测响应；保留迟到结果；旧已判分记录不冒充新故障 | test_account_queues |
| 待提交计划、submit_attempted | 精确原测验评分回读；明确提交前中止只解一次 | test_submission_readback、test_course_grading |
| 弹题尝试记录 | 重新观察并核对本题明确平台回执；未知结果保留 | test_account_queues、test_course_direct |
| 考试保存/交卷保护、标签页绑定 | 同试卷独立回读；新页只有在身份唯一且旧卷已结算时接管 | test_exam_batch、test_exam_finish、test_browser_recovery、test_exam_browser_integration |
| 浏览器关闭与进程租约 | 已确认关闭才走单账号恢复；OS锁释放证据，不删除锁文件强占 | test_workspace_controls、test_account_lease、test_browser_handoff |
| 页面加载与媒体恢复额度 | 同账号有界退避；正常播放后结束旧故障周期 | test_runtime_resilience、test_media_readiness、test_fault_lock_lifecycle |
| 人脸/验证码、邮件去重 | 本人完成后核验；新二维码正常刷新和去重发送 | test_smtp_notifications、test_notification_interval |

故障注入使用隔离状态与浏览器夹具，不故意损坏当前账号、不强杀服务、不重复真实提交。持续网络故障、身份冲突、真正无响应的原操作仍可能使当前账号等待；等待会保留具体原因，其他账号继续。

并发邮件测试曾复现先初始化后加锁造成的 `PermissionError`。修复使用先锁后初始化；Windows支持锁定文件末尾之外的字节范围，依据[Microsoft文件锁说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)。回归包含四轮同步起跑的六线程首次创建，只使用模拟SMTP。

# 网页播放进度同步分析

分析入口：开箱 / reverse-skill → reverse-engineering-api。复用现有 StudyFlow 浏览器和只读播放器诊断，未新建登录会话或修改平台报告。

原链路为后台 `_read_live_sample` 每2秒 evaluate视频属性 → 状态缓存 → 桌面事件推送。页面已有媒体状态事件，但未用 `timeupdate` 同步位置，因此出现重复读取。

实测当前播放器 `reportTimeInterval=60`，自然发生的报告响应间隔约59–61秒；HTTP 200 与 `isPassed` 分别记录。视频播放时间、上报位置、任务目录完成是三个不同观测，不能相互替代。

新链路为媒体原生事件 → 带视频身份校验的只读回调 → 后台缓存 → 桌面事件推送。timeupdate最多每250毫秒推送一次，不使用页面计时器、拖动或人为累加；事件静默15秒后才兜底读取。监听初始化和必要的状态守护仍保留。

回归覆盖暂停、播放结束、多个视频先后切换、旧页面事件、旧订阅事件、乱序事件和无效数值。当前已登录账号保留原浏览器 generation，热加载后事件数持续增长、兜底读取计数保持不变。具体发布验证见同版本测试报告。
